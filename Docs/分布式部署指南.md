# NAS 分布式部署指南

## 概述

本指南介绍如何配置NAS系统的分布式部署，其中当前主机作为存储服务器，所有文件上传和下载都访问这台机器的指定存储路径。

## 系统要求

- Windows 10/11
- Node.js 14+
- MongoDB 4.4+
- PowerShell 5.0+ (推荐)

## 配置步骤

### 1. 运行配置脚本

#### 方法一：使用批处理脚本 (推荐)
```cmd
cd scripts
deploy-config.bat
```

#### 方法二：使用PowerShell脚本
```powershell
cd scripts
.\deploy-config.ps1
```

### 2. 配置参数说明

配置脚本会询问以下参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 服务器端口 | 5000 | 服务器监听的端口号 |
| 存储绝对路径 | F:\Code\NAS_DEMO\NAS\storage\uploads | 文件存储的绝对路径 |
| 存储主机IP | 10.172.79.26 | 存储服务器的IP地址 |
| 存储主机名称 | storage-server | 存储服务器的主机名 |
| MongoDB连接URI | mongodb://localhost:27017/nas | MongoDB数据库连接字符串 |
| JWT密钥 | nas_secret_key | JWT认证密钥 |
| 最大文件大小 | 21474836480 | 单个文件最大大小(字节) |
| 默认存储配额 | 536870912000 | 用户默认存储配额(字节) |

### 3. 启动存储服务器

配置完成后，运行启动脚本：

```cmd
cd scripts
start-storage-server.bat
```

## 分布式架构说明

### 存储服务器配置

当前主机作为存储服务器，具有以下特点：

1. **统一存储路径**: 所有文件都存储在 `STORAGE_PATH` 指定的绝对路径
2. **网络访问**: 其他客户端通过 `STORAGE_HOST_IP` 访问存储服务
3. **主机标识**: 使用 `STORAGE_HOST_NAME` 标识存储服务器

### 环境变量配置

配置脚本会自动创建 `server/.env` 文件，包含以下关键配置：

```env
# 分布式存储配置
STORAGE_HOST_IP=10.172.79.26
STORAGE_HOST_NAME=storage-server
STORAGE_PATH=F:/Code/NAS_DEMO/NAS/storage/uploads

# 文件上传配置
UPLOAD_PATH=F:/Code/NAS_DEMO/NAS/storage/uploads
```

### 文件访问逻辑

1. **上传文件**: 文件直接保存到 `STORAGE_PATH` 指定的绝对路径
2. **下载文件**: 从 `STORAGE_PATH` 指定的绝对路径读取文件
3. **静态服务**: 通过 `/uploads` 路径提供文件静态访问

## 网络配置

### 防火墙设置

确保以下端口开放：
- **5000**: 服务器API端口
- **27017**: MongoDB端口 (如果使用远程数据库)

### 网络访问

其他客户端可以通过以下方式访问存储服务：

```
http://10.172.79.26:5000/api/files/upload
http://10.172.79.26:5000/api/files/download/:id
http://10.172.79.26:5000/uploads/:filename
```

## 故障排除

### 常见问题

1. **MongoDB连接失败**
   - 检查MongoDB服务是否启动
   - 验证连接字符串是否正确

2. **存储路径不存在**
   - 确保指定的存储路径存在
   - 检查路径权限

3. **端口被占用**
   - 更改服务器端口
   - 检查是否有其他服务占用端口

### 日志查看

服务器启动时会显示以下信息：
```
🚀 Server running on http://localhost:5000
📁 Storage path: F:\Code\NAS_DEMO\NAS\storage\uploads
🌐 Storage host: 10.172.79.26 (storage-server)
```

## 安全建议

1. **修改默认JWT密钥**: 在生产环境中使用强密钥
2. **配置防火墙**: 限制网络访问
3. **定期备份**: 备份重要数据和配置
4. **监控日志**: 定期检查服务器日志

## 扩展配置

### 多存储节点

如需配置多个存储节点，可以：

1. 修改 `STORAGE_HOST_IP` 为负载均衡器IP
2. 配置多个存储路径
3. 实现文件分发逻辑

### 高可用配置

1. **数据库集群**: 配置MongoDB副本集
2. **存储冗余**: 配置RAID或分布式存储
3. **负载均衡**: 使用Nginx等反向代理
